# 운영 UI 정리 (2026-11-04)

## 사용 흐름

- 운영 콘솔을 기본 진입점으로 사용한다. 독립 도구는 시작 화면의 고급 메뉴에서 연다.
- 기본 메뉴는 모니터링 / 운영 관리 / 관리로 묶고, 관련 세부 페이지는 업무 상단에서 전환한다.
- 장비 관리: 목록, 등록, 그룹.
- 자산·랙: 장비 자산, 랙 현황, 3D 모델과 건축 자산.
- 데이터 수집: 상태, 작업, MQTT 저장, 실시간 값. MQTT 연결·식별자·매핑·메시지 진단은 고급 메뉴.
- 설정: 위치, 장비 모델, 화면 구성, 공통코드, 사용자.
- 사용 가이드는 실제 시작 순서와 편집 방법을 안내한다. 오래된 API 구현 현황표는 제거한다.

## 구현 원칙

기존 페이지 ID, API, 로그인 전달, 임베디드 메시지, 저장 동작을 보존하면서 탐색을 통합한다. 숨김 위젯 목록과 사용하지 않는 미리보기 코드는 제거하되, 실제 대시보드가 호출하는 편집 모달과 계산 지표 편집기는 유지한다.

`ops-navigation.js`를 메뉴·이름·업무 묶음의 기준으로 사용한다. 복원과 직접 링크는 등록된 페이지와 권한을 함께 검증한다. `ops-workspace.css`는 공통 작업 화면과 내비게이션의 스타일을 담당한다. 두 정적 자산은 보안 허용 목록에 포함한다.

페이지를 전환하면 세션의 선택과 주소의 `page` 값을 함께 갱신한다. 직접 주소로 분석 화면을 연 다음 다른 화면으로 이동해도 새로고침 시 마지막 화면을 유지한다. 미저장 변경 때문에 이동을 취소하면 주소도 바꾸지 않는다.

위젯 대시보드의 미저장 판단은 편집 모드 진입 자체가 아니라 실제 도면·위젯 배치 변경을 기준으로 한다. 빈 위젯 안내는 독립 데이터 보드에만 표시하고 2D·3D 도면 위에는 표시하지 않는다.

## 검증

페이지 스크립트 문법, 메뉴와 실제 패널의 일치, 하위 화면 복원, 권한, 저장하지 않은 변경 보호, 기존 위젯과 3D 동작 테스트를 확인한다. 브라우저 자동 확인은 도구가 URL을 판별하지 못해 중단되어 이번 검증은 코드와 자동 테스트 중심이다.

## 추가 확인

매니저 재시작 후 관리자·일반 사용자·조회 사용자로 각 업무를 순회한다. 도면 및 위젯의 편집·취소·저장, 랙 상세, 장비 등록, MQTT 연결 설정, 새로고침 위치 복원과 작은 화면 배치를 실제 환경에서 확인한다.

## 백엔드 검토

50개 REST 컨트롤러와 UI·수집 서비스 호출을 검토했다. 이미 매핑이 비활성화되고 실사용 참조가 없는 `LoraLookupController`와 `LoraLookupService`, 전용 테스트를 제거했다. 현재 Sensor Data의 통합 MQTT 조회 API는 유지한다. 나머지 구형 LoRa 호환 API는 배포된 외부 호출 여부를 확인해야 하므로 유지한다.

인증 구조의 API Key 범위, access/refresh 토큰 구분, 공개 회원가입 정책, 공용 실시간 수집 세션 소유권은 후속 검토가 필요하다. 이는 화면 정리와 별개로 운영 중인 서비스 인증과 계정 정책에 영향을 주므로 이번 UI 변경에 섞어 전환하지 않는다.

자동 검증 결과:

- 서버: Java 17에서 `mvnw.cmd -o -q clean test`, 642개 중 641개 통과·1개 건너뜀, 실패·오류 0개.
- 화면 로직: `node --test src/test/js/*.mjs src/test/js/*.cjs`, 93개 통과.
- HTML 6개: ID 중복 없음, 인라인 스크립트 문법 확인. 메뉴·3D 자산 모듈 문법 확인.
- 정적 파일 허용 목록, 실제 메뉴 대상, 하위 페이지 복원·직접 주소, 권한, 미저장 상태를 검증했다.

실제 운영 데이터에 대한 전체 브라우저 순회는 컴퓨터 사용 제한으로 미완료다. 이번 화면 정리에 별도 DB 변경은 없으며, 기존 양문형 랙 작업은 별도 마이그레이션 파일을 유지한다. 변경 사항은 작업 브랜치에 있으며 이 정리 작업에 대한 커밋·배포는 아직 하지 않았다.
