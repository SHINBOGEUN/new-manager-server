설명

위치 = 장비의 주소

장비는 반드시 위치 코드에 매핑됩니다. 미지정은 UNASSIGNED를 씁니다.

  • 트리는 children 재귀 구조로 내려옵니다.
  • 드래그 이동 → PATCH /{code}/parent · body { parentCode }
  • 하위 포함 삭제와 단일 삭제를 버튼으로 분리하세요.
  • 위치 선택 시 하위 장비 목록을 같이 보여 주면 운영이 편합니다.
LOCATION_TYPE: UNASSIGNED · SITE · ROOM · ZONE · CONTAINER · ROW · RACK. 계층 제약은 코드의 sortOrder 순서를 따릅니다.

2 장비 등록 마법사

devices → endpoints → snmp-instance → task group
STEP 1기본 정보
STEP 2통신(IP)
STEP 3수집 연결
STEP 4완료

① 장비 기본 · POST /devices

필수: modelId, locationNodeCode, name

② 통신 Endpoint · POST /devices/{id}/endpoints

host + port 조합 유니크

조건부 · SNMP Instance

모델 point에 requiresInstance=true 가 있을 때만. POST …/endpoints/{endpointId}/snmp-instance

③ 수집 그룹에 붙이기

PUT …/collector/tasks/{taskId}/groups/{groupId}
설명

왜 한 번에 안 끝나나

서버에서 장비·통신·수집이 테이블이 갈립니다. UI는 마법사로 묶어 줘도, API는 단계 호출입니다.

  • ① 장비 row 생성
  • ② 그 장비의 IP/포트
  • ②-b MIB instance (필요할 때만)
  • ③ 이미 있는 Task 그룹에 deviceId 추가
instance가 필요 없는 모델에 snmp-instance를 치면 “no snmp point requiring instance” 로 실패합니다. UI에서 숨기세요.

4 수집 작업

POST /api/manager/collector/tasks

Task 생성

모델 1개 + 주기 그룹 N개

groups[0] · 주기 그룹

설명

Task ≠ 장비

Task는 “이 모델의 SNMP를 어떤 주기로 돌릴지” 정의입니다. 실제 장비는 그룹의 deviceIds에 들어갑니다.

  • 보통 모델당 Task 1개 + 1분 그룹
  • 장비 등록 마법사 ③에서 그룹에 합류
  • 그룹을 옮길 때는 기존 그룹에서 장비를 제거한 뒤 새 그룹에 추가
  • Collector 서버로 스펙이 동기화됩니다
UI에서 cron 프리셋(1분/5분/10분)을 주면 실수가 줄어듭니다.

5 화면 위젯

POST /widgets · GET /query/last · /count · /chart · /aggregate

위젯 생성

카드 1장 = 위젯 1개

last 일 때 · 장비 + point *

count 일 때 · 장비 선택 없음

대상은 DB devices.enabled=1 전체. deviceIds/pointNames는 보내지 않거나 [].

미리보기: GET /api/manager/query/count?widgetId= (± countMode override)

chart 일 때 · 시계열

1대상 방식
2장비/모델
3측정항목
4기간
PDU 단상: 합계·장비별·위치별. 3상 포함: 합계·장비별·상별·위치별. 혼합 상별 보기에서는 L1/L2/L3와 단상 시리즈를 함께 표시합니다.
미리보기: GET /api/manager/query/chart?widgetId=&rangePreset=&window= · 문서 docs/query/QUERY_CHART_API.md

배치 layout (선택) · 대시보드 드래그용

chart 카드는 라인 차트 가독성을 위해 h=16 권장 (last/count는 8).

aggregate 일 때 · 측정항목 우선

1측정항목
2호환 장비
3집계 기간
조회: GET /api/manager/query/aggregate?widgetId=&rangePreset=. PUE는 aggregate preset이 아니라 별도 API로 분리합니다.
설명

표시는 UI, 계산은 서버

위젯은 조회 정의입니다. 카드 디자인·차트 종류는 프론트 몫입니다.

  • last — 장비·point 필수 → /query/last
  • count — 장비 없음. enabled 전체 → /query/count
  • countMode: total / by_model / model(+countModelId)
  • chart — point 필수 · devices|models → /query/chart
  • 차트 ENERGY 제외 · 동일 단위만 허용 · PDU 여부에 따라 시리즈 옵션 제한
  • aggregate — point를 먼저 고르고 호환 장비만 선택 → /query/aggregate
  • aggregate op: ENERGY→usage, POWER→power 자동 결정
생성 순서: last=장비→항목, count=방식, chart=대상 방식→대상→항목→기간, aggregate=항목→호환 장비→기간.
규칙 문서: docs/device/PAGE_WIDGET_API.md, docs/query/QUERY_COUNT_API.md, docs/query/QUERY_CHART_API.md, docs/query/QUERY_AGGREGATE_API.md
DB: page_widget core + kind별 1:1 확장(page_widget_aggregate / _count / _chart). 폼·API JSON 필드명은 동일.
레이아웃은 드래그 후 PUT /widgets/{id}/layout
